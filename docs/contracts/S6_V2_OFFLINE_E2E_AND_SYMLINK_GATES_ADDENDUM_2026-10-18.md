## 1. Scope and authority

This addendum records the root-adjudicated, bounded procedure for the
remaining offline two-process handoff and Windows symlink validation gates.
It supplements the parent activity-scoped correction contract and related
addenda only for the procedures stated here. All other parent-contract
requirements, safety invariants, and operational limits remain in force.

The procedure is limited to a new isolated test dispatcher in
`Invoke-S6V2Proof.ps1`, the existing synthetic lifecycle test, and the two
existing symlink tests. The dispatcher may invoke only the exact synthetic
pytest test specified below, with a fresh isolated root. This bounded
authorization does not reopen the full audit or authorize a real proof.

Only these files are authorized for this bounded implementation and
documentation:

- `tools/manual_proofs/Invoke-S6V2Proof.ps1` — add only the isolated
  test dispatcher described here;
- `tests/manual_proofs/test_s6_v2_proof_harness.py` — make only the changes
  required to the specified synthetic test and its assertions;
- `docs/contracts/S6_V2_OFFLINE_E2E_AND_SYMLINK_GATES_ADDENDUM_2026-10-18.md`.

No change is authorized in the launcher's `Execute` branch or its preflight,
the operational downloader or harness behavior, operational limits, or
canonical contracts. The dispatcher must not route into those paths.

## 2. Launcher-mediated synthetic handoff

The launcher's new `OfflineE2E` dispatcher shall invoke only the exact
existing synthetic two-process lifecycle pytest test, using a single fresh,
isolated test directory. It shall not accept a test selector or other input
that can change the selected test or route execution elsewhere. The required
execution chain is:

```text
launcher -> pytest -> existing synthetic test -> harness.execute -> Popen -> two independent child processes
```

The test shall use the synthetic gateway and exercise the actual process
spawn, planned phase-one interruption, checkpoint handoff, phase-two resume,
prefix reread, overlap verification, synthetic completion, and SQLite/ledger
reconciliation. Each process shall produce its own complete report, and the
test shall validate both reports and the handoff evidence.

The timeout receipt shall be generated by the actual monotonic-deadline
calculation. The test fixture may set an aggregate deadline of 60 seconds to
produce and validate a decimal `timeout_effective_seconds` receipt. For each
phase, the test shall compare the reported effective timeout with the
aggregate deadline the supervisor actually applied to that same phase; a
receipt detached from that applied deadline does not pass. This fixture value
does not change any operational timeout constant or limit; the receipt must
not be fabricated, rounded, or truncated for the test.

`OfflineE2E` is test-only and shall not invoke the launcher's `Execute` branch,
access the credential vault or protected session, make network or Telegram
calls, initiate authentication, prompt with `Read-Host`, or touch operational
SQLite files or `.part` artifacts. All generated test artifacts shall remain
inside the one fresh test directory. The existing `Execute` branch and
preflight, and operational downloader/harness paths and limits, shall remain
outside the dispatcher and unchanged.

## 3. Windows symlink security gates

Run both existing real-filesystem symlink tests in the authorized, non-elevated
Windows context with its current privileges. Do not change Windows privileges,
disable protections, or elevate a process to enable symlink creation.

The tests shall use a sentinel target outside the authorized root and establish
that the external path is rejected, the protected sentinel remains unchanged,
and cleanup removes only the symlink created by the test. Cleanup shall not
delete, rewrite, or otherwise mutate the external sentinel or unrelated files.

If symlink creation fails, including with Windows error `1314`, or the current
context otherwise cannot create the required link, classify the real symlink
gate as `BLOCKED_BY_WINDOWS_PRIVILEGE`. Such a result is not `PASS` and must
not be represented as validated security behavior.

## 4. Acceptance boundary

The offline handoff gate passes only when the launcher-mediated test completes
the specified two-process synthetic lifecycle and validates both individual
reports, the decimal timeout receipt, prefix and overlap checks, synthetic
completion, and SQLite/ledger reconciliation.

The real symlink gate passes only when both tests execute with actual symlinks
and provide the rejection, sentinel-preservation, and test-scoped-cleanup
evidence specified above. A skipped test or unavailable symlink capability is
not a pass.

No real Telegram calls, `Execute`, credential access, protected-session access,
or changes to operational artifacts are authorized by this addendum. It does
not declare offline acceptance, formal S6 acceptance, or a sprint checkpoint;
those statuses require their separately defined acceptance evidence.

## 5. Adjudication of offline lifecycle validation

The native PowerShell execution failed in the external lifecycle test after
the harness reported `PROOF_RESULT=PASS`: the test configured `probe=False`,
then read `s6-probe.jsonl` and required `B06` evidence by PID. The authorized
fixture correction in that same test is `probe=True`, with the default
`loop_policy` retained and `S6_V2_TEST_PROBE_TIMEOUT_SECONDS=60` to preserve
the aggregate 60-second deadline. The decimal timeout receipt shall come from
the applied deadline calculation, not be fabricated, and the test shall
compare it with the deadline actually applied.

At the initial adjudication, the offline gate remained `FAIL` pending the
launcher-mediated test completing with exit code 0. Subsequently, the
launcher-mediated `OfflineE2E` completed with exit code 0 and passed, as
recorded in `docs/reports/S6_RUNTIME_ISOLATION_2026-10-18.md`. Exit code 0
remains a condition of acceptance. This adjudication authorizes no
operational, credential, network, downloader, V1/V2, canonical-contract, or
Git change.
